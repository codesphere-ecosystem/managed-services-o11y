The rg Alloy now copies the `managed-services.codesphere.com/name` pod label, the service name sanitized by the provider, onto CNPG metrics and pod logs next to the ID (codesphere-cloud/codesphere-monorepo#23316). The Postgres dashboards still showed only IDs, or took names from a join over 30 days of marketplace events.

## Changes
- **Postgres overview**
  - The service picker lists `name (ID)`, so it's searchable by either. Its value stays the ID, so the alerts' `var-service=<id>` links still work.
  - The Status table reads the name from `cnpg_collector_up` instead of the marketplace events.
  - Time-series legends show `name (ID)`, or the ID for series without the label. Panels still filter on the ID. CPU, memory and disk keep one row per pod, so a pod seen with and without the label isn't counted twice.
  - Plan utilization legends use the marketplace metric's own `name`.
- **Postgres logs and events**
  - The service picker lists `name (ID)`.
  - Pod log lines carry `service_name`.
- Table columns are renamed to *Service ID* and *Service name*, as on the events dashboard (#5).
- README: the rg Alloy row and the note on where names come from.

Alerts are unchanged. Adding a `name` label would change every alert instance's identity, so that's left for a separate change.

## Notes
- Services without the label (before the rollout, or if the marketplace sends no name) show their ID.
- Around the rollout, a service's time series can show up twice, once under its ID and once under its name, until the old points leave the time range.
- The JSON is valid, but the SQL hasn't been run against ClickHouse. Check the Postgres dashboards on a landscape after deploy.
